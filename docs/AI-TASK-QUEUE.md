# AI 任务队列

桌面侧边栏和 iOS 导航提供「任务队列」。单词生成、Mac 文档制卡、已有卡片重新生成都先提交任务，切换页面不影响生成。队列最多同时执行 3 个 AI 请求，结果需逐张阅读、修改并确认。

## 审核

- 「待审核」显示尚未确认的卡；「进行中」显示排队和执行任务；「需处理」显示失败或暂停任务；「已结束」显示完成和取消任务。
- 正向和反向卡分别确认或丢弃，共享词条关联。首版没有批量确认。
- 编辑支持 Markdown、例句、标签和牌组。「保存草稿」不写正式卡片；「确认入库」只提交当前卡，然后打开下一张待审核卡。
- 「确认替换」保留原卡 ID、关联、学习进度和历史。原卡内容、标签或牌组已变化或原卡已删除时，拒绝覆盖；继续学习导致的进度变化不影响替换。
- 草稿重新生成也排队，当前版本保留到成功；若期间已编辑、确认或丢弃，迟到的生成结果不能覆盖它。
- 待审核内容不进入正式库、学习队列、统计或 Watch。新卡确认仅计新增数量，不消耗当日学习额度。

## 持久化与恢复

| 平台 | 队列位置 |
| --- | --- |
| Mac | `~/.vword/ai-tasks.json`，原子替换 |
| iOS | 本地库目录下的 `local-ai/ai-tasks.json`，原子替换 |
| 其他 Tauri 端 | SQLite 的 `ai-tasks-v1` 设置项 |
| Web / Android WebView | IndexedDB `vibe-word-ai` |

任务与草稿不跨设备同步，也不保存 API Key。执行时读取当前配置，并记录实际模型。图片存为本机草稿中的实际字节；图片失败保留文字草稿和提示。

应用关闭或重启后，未完成任务变为暂停，必须手动继续；iOS 进入后台也暂停网络任务。关闭期间不保证继续生成。文档继续时跳过已经保存的分析段和候选。任务不会因 5 分钟超时消失；用户可以手动清理已结束记录，仍有待审核草稿的取消任务不会被清理。

确认接口使用稳定草稿 ID：Mac/iOS 的正式 add/edit 事件作为提交凭据；SQLite 在同一事务提交卡片、进度、统计和凭据；浏览器使用写前日志恢复正式库写入。即使正式提交后退出、尚未更新草稿状态，重试也不会重复新增、重置进度或恢复已删除的卡片。

旧 Mac `document-imports.json` 首次打开时迁入新队列，双向草稿拆为两张，保留来源、共同词条关联和旧 `custom:import:` ID。已接受记录保持已确认。旧文件保留作为迁移来源，不再通过添加页面审核。

手动创建、规范 CSV/JSON 和 Anki 导入保持直接入库。文档解析仍只支持 Mac；其他主应用端支持单词生成和重新生成。正式卡沿用已有同步能力。

## 验证

- `node scripts/test-ai-confirmation.mjs`：浏览器写前日志、空间不足后的恢复、提交凭据和替换冲突。
- `node scripts/test-ai-queue.mjs`：审核隔离、并发上限、编辑、取消迟到结果、保存失败重试、恢复和旧任务迁移。
- `node scripts/test-ai-queue-browser.cjs`：隔离浏览器与虚构模型接口，验证逐卡确认、图片、重启、替换进度和 390px/320px 布局。需要 Playwright，可设置 `PLAYWRIGHT_MODULE`、`CHROME_EXECUTABLE`、`STUDY_TEST_URL`。
- `swift test --package-path ios --filter AITaskTests`：本机草稿恢复、幂等确认、不复活删除卡片和替换冲突。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib ai_tests`：SQLite 确认事务、统计和冲突回滚。
- iOS `VibeWordUITests.testAITaskReviewAndRestart`：隔离模拟器测试库，确认一张后自动进入下一张，重启仍保留待审核状态。
